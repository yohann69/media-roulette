# Media Roulette

A free, open-source party game: everyone's phone picks random photos and videos from their library, and players race to guess whose picture is on screen.

## How to play

Everyone joins with the 6-digit PIN, the QR code, or an invite link shared from the lobby. Each phone picks random media; you can swap anything you'd rather not share, and hold your own photo during a round to hide it. Then guess whose photo is on screen: a correct answer is worth 500 points plus up to 500 for speed, with a bonus for streaks.

- **Photos, Videos, Mix:** what gets picked from each library.
- **Blind Mode:** the media is picked for you, with a 10-second window to remove anything.
- **Time Machine:** also guess the year the photo was taken (up to 300 bonus points).
- **Slow Reveal:** every fourth photo starts blurred and sharpens as time runs out.

Send reactions during the results, rematch in the same room to play a series, and share a recap image of the podium at the end.

## Project layout

- `frontend/`: the mobile app (Expo SDK 58, React Native, expo-router)
- `backend/`: the game server (Node.js, TypeScript, Express, Socket.IO). The server is authoritative: it runs the round timers, measures answer times, and lets players who drop out resume their seat for 60 seconds.

## Running locally

Requirements: Node.js 22 or 24 (even-numbered releases), Xcode for iOS and/or Android Studio for Android.

```bash
cd backend
npm install
npm run dev          # TypeScript server with reload, port 6969 (override with PORT)
npm test             # unit + integration tests
npm run build && npm start   # production: compiles to dist/ and runs it
```

```bash
cd frontend
npm install
EXPO_PUBLIC_SERVER_URL=http://localhost:6969 npx expo run:ios   # or run:android
```

`EXPO_PUBLIC_SERVER_URL` points the app at your own server. Without it, the app uses the public game server.

The native `ios/` and `android/` folders are generated by `npx expo prebuild` and are not committed.

## Self-hosting the server

The server is a single Node.js process with no database: rooms live in memory, and media is kept on disk only for the length of a game.

```bash
cd backend
docker build -t media-roulette-server .
docker run -p 6969:6969 media-roulette-server
```

Or without Docker: `npm ci && npm run build && npm start` (Node.js 22 or 24).

| Variable | Default | What it does |
| --- | --- | --- |
| `PORT` | `6969` | Port to listen on. |
| `UPLOADS_DIR` | `backend/uploads` (`/data/uploads` in Docker) | Where encrypted media is kept during a game. |

Put it behind HTTPS (any reverse proxy, or a host such as Railway, Render or Fly.io that provides it), then build the app with `EXPO_PUBLIC_SERVER_URL=https://your-server.example`. Invite links shared from the lobby point to `https://your-server.example/j/<PIN>`, a small page served by the game server that opens the app on the join screen.

## How media is handled

- **Prepared on the phone.** Photos are resized (longest side 1440 px) and re-encoded, which strips location and camera metadata. Videos are cut to a short clip and re-encoded at 720p.
- **Only what's played leaves the phone.** When the host starts the game, the server picks the deck and asks each owner for just those items. The rest of your selection is never uploaded, and your own media is shown from your phone, never downloaded back.
- **End-to-end encrypted.** The host's phone creates a random room key. It's passed between phones sealed to each player's X25519 public key, and media is encrypted with XChaCha20-Poly1305 before upload. The server only stores and relays ciphertext it can't read.
- **Short-lived.** The server deletes media when the game ends, when a player leaves, after 15 minutes of inactivity, and in any case after 3 hours. Phones delete downloaded media at the end of the game and on the next launch.

Note: the server hands out the players' public keys, so a malicious server could in theory substitute its own keys (an active attack). The encryption protects against everything passive: stored files, logs, backups, or someone browsing the server's disk.
